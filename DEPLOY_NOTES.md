# Ωboy V0.22.0 — Deploy Notes

## Netlify settings (unchanged)
- Build command: **leave blank**
- Publish directory: `.`
- Functions directory: `netlify/functions`

There is no `package.json` and no build step. Everything is static plus CommonJS functions.

## Jackson

Jackson is now embedded directly in `index.html` as a base64 WebP data URI
(~91 KB, transparent background).

The asset was never actually missing from the repo zip —
`assets/jackson-ohmboy-mascot.png` was present and valid. So the 404 was the
file not reaching the published directory, which is why hardening the path in
v0.21.6 didn't fix it. Rather than keep chasing that, the dependency is gone:
the image ships inside the HTML and cannot 404.

`assets/` is now optional. It's kept only as the source artwork for future
edits. The five duplicate mascot PNGs were removed (~5.4 MB).

## Procore setup (item 9)

Set these in **Netlify → Site settings → Environment variables**, then redeploy:

| Variable | Value |
|---|---|
| `PROCORE_CLIENT_ID` | from your Procore app |
| `PROCORE_CLIENT_SECRET` | from your Procore app |
| `PROCORE_REDIRECT_URI` | `https://<your-site>/.netlify/functions/procore-auth-callback` |
| `PROCORE_OAUTH_BASE` | `https://login.procore.com` (sandbox: `https://login-sandbox.procore.com`) |
| `PROCORE_API_BASE` | `https://api.procore.com` (sandbox: `https://sandbox.procore.com`) |
| `PROCORE_COMPANY_ID` | read it off the auth callback response |
| `PROCORE_WEBHOOK_SECRET` | a long random string you choose |
| `PROCORE_WEBHOOK_NAMESPACE` | `ohmboy-packets` |
| `PROCORE_SERVICE_USER_ID` | optional, for loop filtering |

`PROCORE_REDIRECT_URI` must match a Redirect URI registered on the Procore app
**exactly**, including scheme and trailing path.

### Order of operations

1. `/.netlify/functions/procore-health` — shows what's configured and what isn't.
2. `/.netlify/functions/procore-auth-start` — authorise. Add `?json=1` to see the
   URL instead of redirecting.
3. The callback prints your companies. Set `PROCORE_COMPANY_ID` and redeploy.
4. `/.netlify/functions/procore-webhook-register` — creates the hook and triggers.
   Safe to run repeatedly; it reuses an existing hook in the namespace.
5. `/.netlify/functions/procore-webhook-deliveries?status=failing` — first stop
   when events stop arriving.

### Two things the receiver guards against

**The five second timeout.** Procore fails a delivery if it hasn't had a 2xx
within 5 seconds, then retries — which is how you get duplicate packets. The
receiver verifies, acknowledges, and only then does work. Measured ack latency
is sub-millisecond. When you add enrichment (fetching the full drawing from the
REST API), it must go *after* the response, on a queue — not inline.

**Feedback loops.** When OhmBoy writes back to Procore, Procore fires an event
for that write and hands it straight back. Events matching
`PROCORE_CLIENT_ID` or `PROCORE_SERVICE_USER_ID` are dropped before the
transform layer.

### Storage is not durable yet

`netlify/functions/_lib/store.js` is in-memory. Netlify functions cold-start,
so tokens and events do not survive. That's fine for wiring and health checks.
**Before you rely on webhook data, swap that one file for a real store** —
everything routes through `get`/`put`/`del`, so it's a single-file change.
Until then you'll need to re-authorise after a cold start.

## Data migration

The localStorage key moved to `ohmboy_v0220_state`, so you start with a clean
slate. A v0.21.x save still loads without throwing if you point the key back —
tested — but CO/RFI rows auto-generated by the old triage flow will be present,
and those logs are now PM-entry only.
